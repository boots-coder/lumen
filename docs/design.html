Lumen 设计文档

模型无关的 AI 编码 Agent SDK — 架构、模块、数据流与扩展点的完整说明

版本 0.5.0 包名 lumen Runtime Python ≥ 3.11 License MIT 依赖 httpx · pydantic · tiktoken · anyio

1. 项目概述

Lumen 是一个生产级、模型无关的 AI 编码代理框架,把 Claude Code / Cursor Agent 这类工具中"工具调用 + 上下文工程 + 推理预算管理 + 安全控制"的整套机制抽象为可嵌入的 Python SDK。它的核心承诺是:

给任意大模型一个 API Key,就能让它具备读、写、分析代码的能力——OpenAI、Anthropic、DeepSeek、Ollama,或任何 OpenAI 兼容协议。

1.1 设计目标

  • 模型无关:Provider 抽象屏蔽各家 API 差异(消息格式、工具调用、思考字段、缓存机制)。
  • 生产可用:重试、限流、abort、权限、Hook、持久化重试都内置;不依赖外部基础设施(向量库、消息队列)。
  • 轻依赖:核心仅 5 个 PyPI 依赖(httpx, pydantic, pydantic-settings, tiktoken, anyio)。
  • 可解释的安全模型:四维特征评分 + Regex 双引擎,五级风险,可向用户解释为什么拒绝。
  • 无侵入嵌入:既能作为 CLI(python chat.py)直接使用,也能作为 SDK 在任意 Python 程序中初始化 Agent。

3. 核心类型与协议

类型定义集中在 lumen/_types.py,是其它所有模块的公共词汇表。

lumen/_types.pypython
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum
from typing import Any, Literal


class Role(str, Enum):
    SYSTEM    = "system"
    USER      = "user"
    ASSISTANT = "assistant"
    TOOL      = "tool"


@dataclass
class ToolCall:
    id: str                          # 唯一 ID(provider 生成或自构造)
    name: str                        # 工具名
    arguments: dict[str, Any]        # 已 parse 的参数(非字符串)


@dataclass
class Message:
    role: Role
    content: str
    token_count: int = 0
    created_at: datetime = field(default_factory=datetime.utcnow)
    is_compact_summary: bool = False
    tool_calls: list[ToolCall] | None = None     # assistant 含工具调用时填充
    tool_call_id: str | None = None              # 当 role == TOOL
    tool_name: str | None = None

    # 关键转换:同一条消息同时支持两种 API 格式
    def to_openai_dict(self)    -> dict[str, Any]: ...
    def to_anthropic_dict(self) -> dict[str, Any]: ...

需要特别注意 Message 的两套序列化方法:

  • to_openai_dict() — 工具结果以 role=tool + tool_call_id 单独成消息。
  • to_anthropic_dict() — 工具结果包装在 user 消息的 content 数组中,类型 tool_result;助手的工具调用则是 type: tool_use 的 content block。
设计 Message 自身负责"知道怎么把自己变成两种格式"——而不是在 Provider 里写转换函数。这避免了 Provider 实现重复处理 tool_calls 的边界条件。

TokenUsage 与上下文窗口

lumen/_types.pypython
@dataclass
class TokenUsage:
    total: int = 0           # 当前上下文里所有消息 + system 的 token 总和
    prompt: int = 0          # 上轮请求送出的 prompt tokens
    completion: int = 0      # 上轮 assistant 输出的 tokens
    context_window: int = 0  # 模型最大窗口
    compaction_count: int = 0

    @property
    def percent_used(self) -> float:
        if self.context_window == 0:
            return 0.0
        return round(self.total / self.context_window * 100, 1)

    @property
    def tokens_remaining(self) -> int:
        return max(0, self.context_window - self.total)

简化伪代码,真实实现见 agent.pypython
async def chat(self, text: str) -> ChatResponse:
    # 1. 写入用户消息
    self.session.append(Message(Role.USER, text))

    # 2. 评估上下文窗口,必要时触发自动压缩
    state = assess_context_window(self.session, self._cfg)
    if self.auto_compact and state.should_compact:
        await self._compactor.compact(self.session, keep_recent=self.keep_recent)

    # 3. 构造静态 system prompt(角色+规则+工具规范+Mode 段),~3KB,可缓存
    system = await self._system_builder.build()

    # 3b. 构造 ContextReminder(cwd + 日期 + Git + ENGRAM),包成 
    #     作为首条 user 消息注入(每个 session 只做一次,memoize)
    reminder = await self._system_builder.build_context_reminder()
    if reminder and not self.session.has_reminder():
        self.session.prepend_reminder(reminder)

    # 4. 工具循环
    for round_idx in range(self.max_tool_calls):
        payload = self._build_payload(system)
        payload = ThinkingManager.prepare_request(self.thinking, self.profile, payload)
        payload = self._cache.prepare(payload, self.profile)

        resp = await with_retry(
            lambda: self.provider.chat(**payload),
            config=self.retry_config,
            abort=self.abort,
        )
        self.session.append(Message.from_provider(resp))

        if not resp.tool_calls:
            break

        # 5. 工具执行(并发/串行 + 权限 + Hook)
        results = await self.tool_executor.run(resp.tool_calls)
        for r in results:
            self.session.append(Message(Role.TOOL, r.output, tool_call_id=r.id))

    return ChatResponse(content=self.session.last_assistant.content,
                        token_usage=self._token_usage())

5. Provider 适配层

5.1 Factory 路由

路由策略简洁明了:看 base_url,再看模型名前缀,默认走 OpenAI 兼容。

lumen/providers/factory.pypython
_ANTHROPIC_BASE = "https://api.anthropic.com"
_OPENAI_BASE    = "https://api.openai.com/v1"

def create_provider(
    api_key: str, model: str, base_url: str | None, timeout: float = 120.0,
) -> tuple[BaseProvider, str]:
    is_anthropic = (
        (base_url is not None and "anthropic.com" in base_url)
        or model.startswith("claude")
    )
    if is_anthropic:
        resolved = base_url or _ANTHROPIC_BASE
        return AnthropicProvider(api_key, model, resolved, timeout), resolved
    resolved = base_url or _OPENAI_BASE
    return OpenAICompatProvider(api_key, model, resolved, timeout), resolved
兼容性 任何 OpenAI 兼容 API(Together / Groq / Ollama / vLLM / LM Studio / DeepSeek)都通过 OpenAICompatProvider 走;只要传入对应 base_url 即可。

5.2 BaseProvider 协议

lumen/providers/base.pypython
class BaseProvider(ABC):
    """各家 LLM API 的轻适配器,负责消息格式 / 工具调用 / 流式三件事。"""

    @abstractmethod
    async def chat(
        self,
        messages: list[dict[str, Any]],
        system: str,
        max_tokens: int,
        temperature: float,
        tools: list[dict[str, Any]] | None = None,
    ) -> ProviderResponse:
        """messages 已经是该 provider 的格式,Provider 只负责发请求和解析响应。"""

    @abstractmethod
    async def stream(
        self,
        messages: list[dict[str, Any]],
        system: str,
        max_tokens: int,
        temperature: float,
    ) -> AsyncIterator[str]: ...

注意 Provider 拿到的 messages 已经是该家 API 的字典格式(由 Message 的 to_*_dict() 完成转换),Provider 内部不再做语义转换,只做拼装与 HTTP IO。

5.3 Anthropic 实现要点

  • 使用 POST https://api.anthropic.com/v1/messages,头部 anthropic-version: 2023-06-01。
  • 工具调用映射:返回 content 数组里 type=tool_use 块解析为 ToolCall。
  • 系统提示放顶层 system 字段,可以是字符串或带 cache_control 的 block 数组。
  • Thinking blocks 通过 thinking: {"type": "enabled", "budget_tokens": N} 启用。

5.4 OpenAI 兼容实现要点

  • 使用 POST {base_url}/chat/completions。
  • O 系列(o1/o3-*)模型自动适配:用 max_completion_tokens、注入 reasoning_effort、不能设 temperature。
  • 工具调用映射:解析 choices[0].message.tool_calls[*],把 arguments 字符串 json.loads。
  • 支持 SSE 流(data: ...\n\n)。

6. Tool 工具系统

6.1 基类与 Registry

lumen/tools/base.pypython
from abc import ABC, abstractmethod
from typing import Generic, TypeVar
from pydantic import BaseModel

InputT = TypeVar("InputT", bound=BaseModel)


class ToolResult(BaseModel):
    success: bool
    output: str
    error: str | None = None


class Tool(ABC, Generic[InputT]):
    @property
    @abstractmethod
    def name(self) -> str: ...

    @property
    @abstractmethod
    def description(self) -> str: ...

    @property
    @abstractmethod
    def input_schema(self) -> type[InputT]: ...

    @abstractmethod
    async def execute(self, input_data: InputT) -> ToolResult: ...

    def to_openai_schema(self) -> dict[str, Any]:
        schema = self.input_schema.model_json_schema()
        schema.pop("$defs", None)  # OpenAI 不接受 $defs
        return {"type": "function",
                "function": {"name": self.name, "description": self.description,
                             "parameters": schema}}

    def to_anthropic_schema(self) -> dict[str, Any]:
        schema = self.input_schema.model_json_schema()
        schema.pop("$defs", None)
        return {"name": self.name, "description": self.description,
                "input_schema": schema}

所有工具的 input_schema 都是 Pydantic 模型,因此模型给出的参数会经过严格类型校验,避免 LLM 给出脏数据时 tool 抛底层异常。

工具示例:read_file

lumen/tools/file_read.py 概念化python
class FileReadInput(BaseModel):
    path: str
    offset: int = 0
    limit: int = 2000


class FileReadTool(Tool[FileReadInput]):
    name = "read_file"
    description = "Read a file from disk, optionally a slice (offset/limit lines)."
    input_schema = FileReadInput

    async def execute(self, inp: FileReadInput) -> ToolResult:
        try:
            text = Path(inp.path).read_text(errors="replace")
            lines = text.splitlines()[inp.offset : inp.offset + inp.limit]
            numbered = "\n".join(f"{i+1+inp.offset:>6}\t{l}" for i, l in enumerate(lines))
            return ToolResult(success=True, output=numbered)
        except FileNotFoundError as e:
            return ToolResult(success=False, output="", error=str(e))

6.3 ToolExecutor — 并发模型

工具执行不是简单的 for tc in tool_calls: await tool.execute(tc)。services/tool_executor.py 实现了一套基于工具语义的调度:

  • 读类并发:read_file / glob / grep / tree / definitions / web_* 互不影响,用 asyncio.gather 同时执行。
  • 写类串行:write_file / edit_file / bash 排队执行,避免文件状态竞争。
  • Abort 联动:每个工具调用前先 abort.check(),中途也可被外部取消,正在跑的 bash 会收到 SIGTERM。
  • Hook 三段式:pre_tool → execute → post_tool,任一阶段失败可降级或返回补救输出。
  • 结果截断:超过阈值(默认 ~25k tokens)的输出在写回 Session 前用 truncate_tool_result 折叠中部,保留首尾。
tool_executor 调度逻辑(伪代码)python
async def run(self, calls: list[ToolCall]) -> list[ToolExecResult]:
    # 按写/读分桶
    reads, writes = [], []
    for tc in calls:
        (writes if self._is_mutating(tc.name) else reads).append(tc)

    # 读类并发
    read_results = await asyncio.gather(
        *[self._run_one(tc) for tc in reads], return_exceptions=False
    )
    # 写类串行
    write_results = []
    for tc in writes:
        write_results.append(await self._run_one(tc))

    return read_results + write_results


async def _run_one(self, tc: ToolCall) -> ToolExecResult:
    self.abort.check()                       # 取消?
    pre = await self.hooks.pre_tool(tc)
    if pre.behavior is HookBehavior.DENY:
        return ToolExecResult.denied(tc, pre.reason)
    if pre.modified_input:
        tc.arguments = pre.modified_input

    perm = self.permissions.check(tc)
    if perm.behavior is PermissionBehavior.DENY:
        return ToolExecResult.denied(tc, perm.reason)
    if perm.behavior is PermissionBehavior.ASK:
        if not await self.notifier.confirm(tc, perm.reason):
            return ToolExecResult.denied(tc, "user denied")

    try:
        result = await self.registry.get(tc.name).execute(
            self.registry.get(tc.name).input_schema(**tc.arguments)
        )
    except Exception as e:
        post = await self.hooks.post_tool_failure(tc, e)
        if post.recovery_output:
            return ToolExecResult.recovered(tc, post.recovery_output)
        raise

    await self.hooks.post_tool(tc, result)
    return ToolExecResult.ok(tc, truncate_tool_result(result.output))

7. 上下文管理

7.1 SystemPromptBuilder — 渐进式上下文暴露

这是 Lumen 上下文工程里最关键的一块,设计哲学是 progressive context exposure:把"模型需要知道的所有东西"按 静态性 / 体积 / 缓存友好度 拆成三个层级,而不是一股脑塞进 system prompt。

层级内容大小注入位置缓存?
静态 system prompt 角色 · 系统规则 · 工具使用规范 · tone/style · 激活的 Mode 段 ~3KB API 的 system 字段 是
ContextReminder cwd · 当前日期 · Git 状态 · ENGRAM 记忆 1–5KB 首条 user 消息,包在 <system-reminder> 标签里 否
项目结构 文件树 · README · 源码 0(不预加载) LLM 自己用 tree/glob/grep/read_file 按需取 —
为什么这么设计 第一,静态 system prompt 永远不变,Anthropic 的 prompt cache 能稳定命中;Git/ENGRAM 是变量,放进去会让缓存失效。 第二,把动态上下文伪装成 <system-reminder> 包裹的 user 消息,模型可以根据相关性自行忽略——它本质上是"提示"而非"指令"。 第三,传统做法在启动时跑一遍 tree 把目录贴进 system(10–20K tokens),Lumen 完全不预扫描,让 LLM 按需探,冷启动 token 从 ~20K 降到 ~3KB。
lumen/context/system_prompt.pypython
class SystemPromptBuilder:
    """
    三层渐进式暴露 — 初始 token 成本约 1–2K(而非 10–20K)。
    """

    def __init__(
        self,
        extra_instructions: str = "",
        cwd: Path | None = None,
        inject_git_state: bool = True,
        inject_memory: bool = True,
        review_mode: bool = False,
    ) -> None:
        self._extra = extra_instructions.strip()
        self._cwd = (cwd or Path.cwd()).resolve()
        self._inject_git = inject_git_state
        self._inject_memory = inject_memory
        self._modes: ModeStack = build_default_stack()
        if review_mode:
            self._modes.activate("review")
        self._cached_system: str | None = None
        self._cached_context: str | None = None
        self._context_built = False

    async def build(self) -> str:
        """返回静态 system prompt(_BASE_PROMPT + Mode 段 + extra),memoize 一次。"""
        if self._cached_system is not None:
            return self._cached_system
        parts: list[str] = [_BASE_PROMPT]
        mode_prompt = self._modes.build_prompt()
        if mode_prompt:
            parts.append(mode_prompt)
        if self._extra:
            parts.append(self._extra)
        self._cached_system = "\n\n".join(parts)
        return self._cached_system

    async def build_context_reminder(self) -> str | None:
        """
        构造 ... 字符串作为 user 消息注入。
        包含 cwd / 当前日期 / Git 状态(可选) / ENGRAM 记忆(可选)。
        每个 session 只构造一次,后续 memoize。
        """
        if self._context_built:
            return self._cached_context
        self._cached_context = await _build_context_reminder(
            self._cwd, self._inject_git, self._inject_memory,
        )
        self._context_built = True
        return self._cached_context

    def enable_review_mode(self) -> None: ...
    def enable_plan_mode(self)   -> None: ...   # 激活模式会使 _cached_system 失效

_LUMEN_HOME = Path.home() / ".lumen"
_MAX_PATH_COMPONENT = 200

def sanitize_path(path: str) -> str:
    """非字母数字 -> '-',连续 '-' 合并,过长则取 hash 后缀。"""
    sanitized = re.sub(r"[^a-zA-Z0-9]", "-", path)
    sanitized = re.sub(r"-{2,}", "-", sanitized).strip("-")
    if len(sanitized) > _MAX_PATH_COMPONENT:
        suffix = hashlib.sha256(path.encode()).hexdigest()[:12]
        sanitized = sanitized[: _MAX_PATH_COMPONENT - 13] + "-" + suffix
    return sanitized

def get_transcript_dir(cwd: Path) -> Path:
    return _LUMEN_HOME / "projects" / sanitize_path(str(cwd))

7.4 自动压缩

压缩决策模块位于 compact/auto_compact.py,核心是 三个阈值:

lumen/compact/auto_compact.pypython
AUTOCOMPACT_BUFFER_TOKENS: int = 13_000  # 触发压缩前的安全头部
MAX_OUTPUT_RESERVE: int       = 20_000  # 给 summary 输出预留
MAX_CONSECUTIVE_FAILURES: int = 3        # 熔断

# 公式
#   effective_window      = context_window - min(max_output_tokens, MAX_OUTPUT_RESERVE)
#   autocompact_threshold = effective_window - AUTOCOMPACT_BUFFER_TOKENS
#
# 例:200K 窗口 / 32K 输出
#   effective      = 200_000 - 20_000 = 180_000
#   autocompact    = 180_000 - 13_000 = 167_000

@dataclass(frozen=True)
class ContextWindowState:
    total_tokens: int
    context_window: int
    effective_window: int
    autocompact_threshold: int
    warning_threshold: int
    blocking_threshold: int

    @property
    def should_compact(self) -> bool:
        return self.total_tokens >= self.autocompact_threshold

    @property
    def is_blocked(self) -> bool:
        return self.total_tokens >= self.blocking_threshold

触发后由 Compactor 调用一次"摘要专用 LLM 调用"——可以是同一个模型,也可以通过 compact_model= 指定一个更强 / 更便宜的:

lumen/compact/compactor.py 概念化python
class Compactor:
    async def compact(self, session: Session, keep_recent: int = 6) -> CompactionResult:
        # 1. 切分:旧的 N-keep 条用于摘要,后 keep_recent 条原样保留
        head = session.messages[:-keep_recent]
        tail = session.messages[-keep_recent:]

        # 2. 调 LLM 生成结构化摘要(see compact/prompt.py)
        summary = await self._summarize(head)

        # 3. 重写 session:摘要为单条 system-like 消息 + tail
        marker = Message(Role.ASSISTANT, summary, is_compact_summary=True)
        session.messages = [marker] + tail

        return CompactionResult(
            summary=summary,
            messages_before=len(head) + keep_recent,
            messages_after=len(session.messages),
            tokens_before=..., tokens_after=...,
            kept_recent_count=keep_recent,
        )

10. 扩展点

10.1 自定义 Tool

from pydantic import BaseModel
from lumen.tools import Tool, ToolResult

class TodoInput(BaseModel):
    action: Literal["add", "list", "done"]
    text: str | None = None
    id: int | None = None

class TodoTool(Tool[TodoInput]):
    name = "todo"
    description = "Manage an in-memory TODO list."
    input_schema = TodoInput

    def __init__(self):
        self._items: list[dict] = []

    async def execute(self, inp: TodoInput) -> ToolResult:
        if inp.action == "add":
            self._items.append({"id": len(self._items), "text": inp.text, "done": False})
            return ToolResult(success=True, output=f"added #{len(self._items)-1}")
        if inp.action == "list":
            return ToolResult(success=True, output=json.dumps(self._items, indent=2))
        if inp.action == "done":
            self._items[inp.id]["done"] = True
            return ToolResult(success=True, output=f"done #{inp.id}")

agent = Agent(api_key=..., model=..., tools=[TodoTool(), ...])

10.2 自定义 Hook

from lumen import HookRegistry, PreToolHookResult, HookBehavior

hooks = HookRegistry()

async def deny_root_writes(tc):
    p = tc.arguments.get("path", "")
    if p.startswith("/etc") or p.startswith("/usr"):
        return PreToolHookResult(behavior=HookBehavior.DENY,
                                 reason="禁止写入系统路径")
    return PreToolHookResult()

hooks.add_pre("write_file", deny_root_writes)
hooks.add_pre("edit_file",  deny_root_writes)

agent = Agent(api_key=..., model=..., hooks=hooks)

13. 性能 & 工程取舍

13.1 为什么不引入向量库?

  • SessionMemory 量级通常 < 200 条事实,TF-IDF + Jaccard 在内存里搜索 ms 级,体验已足够好。
  • 向量库会引入 sqlite-vss / faiss / chromadb 这类重依赖,与"轻量内嵌 SDK"定位冲突。
  • 真正需要语义检索的场景(知识库 RAG)交给上层应用做,Lumen 不替它做选择。

13.2 为什么读类工具并发、写类串行?

  • 读操作语义上无副作用,延迟瓶颈基本是磁盘/网络 IO,并发收益显著。
  • 写操作存在文件状态依赖(edit_file 依赖最新内容),串行执行避免"两个 edit 互相覆盖"的脏写问题——FileEditTracker 也假定单写者。

13.3 为什么 ENGRAM 是 Markdown 而不是 YAML/JSON?

  • 记忆是给 LLM 看的,自然语言段落比结构化字段更易消费。
  • Markdown 标题可以被 LLM 自然识别为分节,无需解析。
  • 用户在编辑器里手写记忆零门槛。
